# Generic tactical collection for future observed runs

This additive producer extends the explicit observed-prefix recorder; it does not
change the fixed Forest source, existing immutable captures or legacy projections.
A new active match can preserve one typed resident manager-settings observation
without a hand-built tactical capsule. Native positive runtime for this extension
is not yet verified: the candidate CLI returned
`checked_empty_viewable_client_inventory`, `artifact_written=false`.

## Normal lifecycle

`fm_record_current_match(session_id, include_tactics=true)` attempts the optional
settings observation by default. `include_tactics=false` or CLI `--without-tactics`
skips it. The event/tracking prefix remains available when tactical validation
fails; its artifact records the unavailable tactical state rather than inventing
an empty plan. No daemon, game writes, native game calls or UI are introduced.

The producer uses `resident_match_plans.inspect` under a query-local rechecked
ReadSet. Existing native guards validate manager ownership, both ordered canonical
teams, instruction masks/labels, mentality and stored phase roles. An optional
source field preserves the exact eleven instruction-selection bytes, including
unnamed selected bits 0 and84–87. Bits1–83 retain their native identities and null
labels where unavailable. Unknown flags never become implied "off" instructions.
The existing source API keeps its previous default output.

Two independently reread playback samples bound the tactical observation window.
Both must retain the same bound fixture/owner/official match identity and monotonic
cursor. The outer recorder still verifies the career/process epoch and its fixed
pass/tracking prefix. The tactics sample can be later than that event cutoff;
`same_tick_as_events_verified=false` makes the distinction explicit. Score and
period are null in this increment, rather than borrowing an earlier event or a
later engine counter. Kickoff settings, effective individual overrides, intent and
exact change time are unknown. A single sample establishes no change history.

## Portable document and trust contract

Schema1 `source_documents` adds `tactical_samples`. Its SHA256 covers exact stored
canonical JSON. The document has:

- `product_type=observed_tactical_samples`, `schema_version=1`, collection state.
- Exact fixture tuple and official match ID, career creation identity, and the
  outer recorder's hashed native incarnation identity.
- Native-guard and source-policy digests under
  `same_source_resident_manager_settings_v1`; no native addresses are persisted.
- One sample with cursor window, event cutoff, observation timestamp, content and
  summary hashes, ordered team settings, raw flags and explicit interpretation
  limits.

The explicit recorder registration adds a separate `producer_attestation` binding
that policy, document ID/SHA, source incarnation and immutable selection ID to the
exact registered original. Ordinary manual registration without this proof does
not gain tactical attestation merely from a plausible document shape. Read-side
validators must check that proof, hash, fixture/career, ordered teams and supported
policy before exposing generic views; collection does not itself enable a view.
The existing hash-pinned legacy Forest attestation remains independent.

Unchanged source selection reuses the existing artifact, even when the optional
observation timestamp changes. Re-registration binds the original stored document
hash, not the later observation time. Existing artifacts are never enriched in
place. Changed settings, raw unknown flags or cursor window create a distinct
immutable capture through the existing content-addressed lifecycle.

## Assist collection remains unavailable

The current recorder stores only pass-family categories6–11. Credited assist bit4
can occur in other categories, including12. Native `GAME_MATCH_PLAYER_STATS` has a
proved Assists byte, but the resident actor graph can omit serialized bench rows;
no complete independent all-player census is presently collected. Engine counters
can also lead the playback cursor. Comparing them to past selected events would
be invalid.

The artifact explicitly records
`complete_independent_counters_and_terminal_all_category_event_scope_not_collected`.
Enabling a future assist view requires complete typed counters including zeros,
all-category source flag preservation, canonical actor/team identities and a
same-run terminal/caught-up temporal gate. No missing player, counter or flag is
filled with zero, and no assist is inferred from consecutive passes.

## Verification

The focused suites cover raw unnamed flags, unknown mentality labels, cursor
windows, career/incarnation/policy mismatch rejection before publication,
optional-scope failure, exact attestation, timestamp dedupe and existing reader
compatibility. They also retain native pass/tracking and source-manager regressions.
Fresh natural-match positive capture remains a separate acceptance requirement.
