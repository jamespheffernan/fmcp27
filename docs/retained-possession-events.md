# Retained possession won/lost events

`fm_get_retained_possession_events` takes an exact result `fixture_ref` from the live fixture tools. Optional team and player selectors restrict output after complete side checks; a selected player requires its team. Pagination uses the first `source_id`. The source is the active coach's retained CBE plus the matching resident native player frame. No saved-file fallback, game input, native function call or UI is used.

Native stats dispatch action14 increments individual `PossessionWon` atD7 and action15 increments `PossessionLost` atD8. The CBE converter maps the same action14 to category52 and action15 to category53. The original side and roster slot select canonical same-fixture PERSON identities. Every player counter, including zero rows, must close for each side before that side publishes any events. If one side fails, its aggregate remains null and no verified events from that side publish; an independently verified other side remains usable. A missing retained source is unavailable, never a zero-event match.

The frozen Newcastle4–1 Nottingham Forest result (11November2030) contains1,965CBE events. All40 player rows close both counters: Newcastle92won/89lost, Forest75won/98lost. This yields354 typed events. These are stored individual action counts; team sums are reconstruction from those players, not a separate independent serialized team oracle.

`source_native_anchor` preserves the directly stored native XY pair and whether it lies in checked native pitch extents. The constructor obtains that pair from the oldest linked spatial ancestry (`engine+20`), so it is **not independently proved to be the exact possession-transition point**. `transition_location` remains null. No coordinates are reconstructed from adjacent passes, no human left/right labels are supplied, and native physical units remain unasserted. Raw start/end clock words are retained without displaying minutes.

## Defended end and half time (13 November 2026)

`native_x` runs across the pitch and `native_y` along it, centred on 0, and the sides change ends at half time, so an anchor alone does not say which third it is in. The retained record answers that itself. Beside its tracking streams it holds a 16-byte orientation profile (CBE `+0x108`): three tick boundaries at which the sides change ends (`-1` = none) and the side that starts positive. The game's average-position and heat maps turn every side the same way with it (native `4895a60`, `live_average_positions.tracking_positive_orientation`, guarded by `TRACKING_NATIVE_SPANS`).

`orientation` in the tool's answer reports `ends_change_ticks`, the periods they bound (`first_half` from 0 to the first boundary, `second_half` to the second; an extra-time period only when the record holds tracking after the second boundary) and, per side and period, `defended_end`: `negative_native_y` or `positive_native_y`. A side the profile calls positive defends the negative end. The profile's answer is `profile_defended_end`; it becomes `defended_end` only when an independent witness agrees: the side's deepest tracked player in that period (its goalkeeper, at least 50 samples) must average 25 native units or more from the centre line on that end. Otherwise the state is `unverified_no_tracking_witness` or `unverified_tracking_witness_disagrees` and the end stays null.

Each event then carries `period`, `defended_end` and `length_fraction_from_own_goal` (0 = own goal line, 1 = the opposition's), and each side `defended_end_by_period` and `anchor_thirds`: possession won and lost by equal third of the length, with the `unplaced` count. Only the length axis places an event: an anchor over a touchline keeps its place, one up to 5 units behind a goal line counts at that end, and an event whose clocks cross a boundary or fall in an unverified period stays unplaced. The fraction places the anchor, with the anchor's caveat above.

Checked on the nine matches retained on the Newcastle save (game date 5 January 2031): in all 36 side-halves the deepest tracked player averaged 36 to 46 units from the centre line on the end the profile gives, and his own possession events sat on the same end. The first boundary (11,122 to 12,050) fell between the last event of the first half and the first of the second in every match. Whether it is the first half's last tick or the second half's first was not established: no host period observation exists for these matches, and no event carried a clock inside the interval. On Newcastle's five matches all 835 events were placed (394 won: 232 in the defensive third, 129 in the middle, 33 in the final third). An inference from the goalkeeper's regains had left 96 of the 394 unplaced.

These events do not establish the tactical question “where did our press win it back or get played through?” Possession won/lost is separate from pressure completion. Native pressure action28 updates the pressure counters but converts to generic category0, which is not a retained uniquely typed pressure event. Therefore `pressure_regain`, `press_played_through`, `pressure_event_id` and the opposing player remain null. No proximity-based winner/loser or pressure linkage is inferred. The next missing edge is a source-backed pressure-to-possession transition relationship or a native consumer proving category52/53 exact transition positions.

Tests use the genuine immutable Forest packet and negative controls for fixture/TEAM/PERSON/slot/hash/counter differences, missing events/actors, duplicate IDs, absent retention, changed native spans, source pins, incomplete full-roster capture and reload; the orientation tests use two profiles read from the save with synthetic tracking (agreeing, disagreeing, shallow and absent witnesses). Tool output has a structured SDK schema and read-only annotations.
