### Run-time refusals the update did not list

Found by calling tools on the running 27.0.1 game; each refused safely, but the static report
called the tool available.

* **Guards apart from their address** (above): now tuples, re-derived (760 guards rewritten).
* **The arm64 slice offset.** `ffp_projection.ARM_SLICE = 0x5ED4000` is the file offset of the arm64
  slice of the 27.0.0 universal plugin; on 27.0.1 it is 0x5F4C000. The FFP projection and the three
  committed-wage modules read code from the plugin file at that offset, so on 27.0.1 they read the
  wrong bytes ("invalid pinned ARM64 Mach-O"). `ffp_projection.arm_slice(file)` now reads the offset
  from the fat header (`ARM_SLICE` stays the fallback for test images without one).
* **Hashed spans whose code changed length.** A `(start, end, sha256)` guard whose two ends map
  to a span of another length was only counted as `unresolved` and never listed, so its tools
  looked available and refused at run time. `address_map.guard_rewrites` now lists it as a changed
  span (`changed_code_length`). On 27.0.1 there are three, all in `committed_wage_spending_core.py`:
  0xCC0014..0xCC0450 (1,084 bytes, 1,080 on 27.0.1), 0x1002B10..0x1002CE0 (464, 444) and
  0x129B5F4..0x129B804 (528, 324). They are emulated by the wage reducer, so club committed wage
  spending stays unavailable until those three functions are compared and proven; not done here.
* **Not a build difference: `club_transfer_history` returned no rows (14 November 2026).** Every
  club's season 2025 stopped at `pthread_condattr_init`, in the constructor of the game's
  `PAST_TRADE` pool, which the running game process had not built. The plugin file of 27.0.0
  stops at the same call. The call is now a no-op like the other lock set-up calls, and a failed
  read is named in the answer (HISTORIES.md, "The PAST_TRADE pool"). The same day, after a save,
  it refused with "game file has unflushed write data": a record appended to
  `retired_person_hist_archive.obs` and still in the game's stdio buffer. Such a FILE is now read
  as the game would read it (HISTORIES.md, "Unflushed write data in a game file"). `PsHi`, listed
  below with that refusal, was not reproduced.

address census ignored every literal under 0x10000, so the four guards kept their pinned addresses.

record gained three one-byte fields (`isWearingFaceMask` 0x37, `isWearingHeadBandage` 0x38,

the same fields at the same offsets.

when it is the address of a native guard, the rewriter translates it, and the four addresses are

### The pinned build's two names differed from its own code

returns (`_ENGLISH_PROJECTIONS`), so a shape reads the same on both builds. The game's screen on a

from the naming route; for id 29 it is `4-2-3-1 DM Wide`, for id 33 `4-4-1-1 2DM`.
