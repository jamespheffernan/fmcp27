# Live FM27 research notes

Validated build: ARM64 27.0.0.2493426. The production reader checks the plugin fingerprint and loaded UUID before using offsets. All operations are read-only. Supported queries cover a loaded career, managed-club rosters, displayed outfield attributes, club/loan links and attribute filters. Whole-save coverage remains unfinished.

## Implemented roots

`world.py` follows plugin RVA `0x56a4b60` to `game_plugin::GAME_UI` and RVA `0x56a4bc0` to `SAVE_SYSTEM`. The save name is a native string at save-system +0x28, and last-saved date is packed at +0x70. The game root supplies creation date (+0x38), creation version (+0x3c), and save count (+0xc8).

The game root +0x58 leads to a structure whose first vector contains active user records. User +0x148 points to the active human manager, also present in the user +0xc0 manager vector. Manager +0x4b0 leads to the contract; contract +0x08 points back to the manager identity subobject, and +0x10/+0x18 identify the team. Team +0x80 points back to the manager and +0x30 identifies the club. The club +0x18 team vector must contain that team.

The managed-team +0x38 vector contains player primary pointers. Newcastle has 28 in the validation career. Club names are native string pointers at +0xc0/+0xc8. Internal duplicate identity integers are checked but not exposed as verified database IDs.

Player +0x2a8 is the common-name handle, independently checked with Luiz Henrique, Beraldo, Chema Andrés and Alberto Costa. Searches match both full and common names. A full-table scan also found a regular player with a null surname handle and a populated common name; this case is covered by native and synthetic tests.

## Stored weather profiles (0.32.0)

WEATHER uses root 0x56D2DB8, table vtable 0x55A1D00, record vtable 0x55CC3A0 and property getter 0x18B2768. The getter delegates four embedded periods at +0x20/+0x38/+0x50/+0x68 to 0x18B3450. Each period has stride 0x18: signed-16 start day at +0, five signed-byte wind weights at +2, five precipitation weights at +7, ten temperature weights at +0xC and signed-byte day/night variance at +0x16. The remaining byte is unexposed. Shared outer switch cases require register tracing to distinguish category prefixes; a case address alone does not identify a field.

The variance getter at 0x18B3D10 compares against 100 and copies the global property at 0x56D63C0 when equal. That property points to a descriptor with vtable 0x569CA88 and RTTI `N6sicore17NULL_TYPED_TRAITSE`. Its first word is a descriptor pointer, not the vtable itself. The ordinary path stores a signed integer. Runtime code at 0x18B6B08 substitutes native 10 for 100. The public decoder preserves raw 100 and returns a null value with `not_specified`; it does not apply the runtime default or claim a physical unit. The inspected wrappers synthesize a temporary period with variance 100; interpolation helper 0x18B03D4 copies only the category weights. The runtime default therefore does not prove that the stored variance controls those paths.

Installed editor definitions label all 88 period fields and bound start days to 0–365, weights to 0–100 and variance to 0–50. The ten temperature labels include Celsius ranges. Runtime generation tables at 0x53A48B4 and 0x53A4904 contain different boundaries: minima -35/-15/-7/1/8/13/19/29/32/36 and upper values -15/-7/1/8/15/20/29/36/43/49.
