# Reader release notes

Version **0.175.0** removes duties. A role in Football Manager 27 has no duty: a player has one role in possession and one role out of possession, and that is all the game shows. The reader had been decoding a flag stored inside each role word and publishing it as Defend, Support or Attack, so answers read "Full-Back (Defend)" for what the game calls Full-Back. In the game's own legal role lists for 25 tactic files (2,548 choices, 71 roles) every role has exactly one value of that flag, so it is internal bookkeeping fixed by the role and not a choice. The tactics tools (`fm_get_managed_tactics` with `include_roles`, the tactical assignments, in-possession positions and player-instruction tools, `fm_get_current_match`, the tactics screen of `fm_get_ui_screen`) return the role's name and stored word and nothing beneath it; recordings made by earlier versions still read, without the field. pi-fm's tactic writer takes a role by name (`{phase, position_index, role}`), finds the one stored word the game accepts for it and writes the same bytes as before; its guides tell the adviser never to write a duty.

Version **0.174.4** makes `fm_db_read` answer `is_injured` for a player as `player_view` does (his injuries leave days still out), and renames the base `player` column that held the game's always-false flag to `starting_injury_listed`, so nothing named `is_injured` disagrees with the injury records. Version 0.174.3 read the newest match's statistics right after the match. The game keeps the end of the newest entry of its match-statistics file in memory for a while, and the reader read the file alone, so `match_team_stats` and `match_player_stats` had no rows for that match and `fm_query_match_data` failed on it until the game wrote the bytes out. Both readers of that file now lay the game's unwritten bytes over the file where the system says they will be written, as 0.174.2 does for the history files. Version 0.174.2 made `club_transfer_history` and `award_history` answer again. Two things stopped them: the reader's emulator refused one set-up call the game makes when it first builds its pool of past-trade objects, so a club with such a record in any season read as having no transfers; and after the game appends to one of its history files and keeps the bytes in memory, the reader refused every read through that file. The emulator now builds the pool in its own memory, and a game file with unwritten bytes is read as the game itself would read it, the buffered bytes laid over the file at the position the system reports, checked against the system's own C library in the tests. A history read that fails is named in the answer (`collections[table].not_read` and a note) and is read again by the next statement; it no longer comes back as an empty result. [docs/fmdb/HISTORIES.md](docs/fmdb/HISTORIES.md) has the account. Version 0.174.1 made `is_injured` in `player_view` true for a player whose injuries leave days still out, the game's own rule for a player who is out; the column came from a table the game leaves empty in a running career and read 0 for every player. The live self-check `scripts/fmdb_validate.py` compares a value only when it is the same before and after the game's getter runs, and accepts the game's -1 for the condition of a player who is out. Version 0.174.0 closed the gaps the reader had on game build 27.0.1. Formation names answer again: `fm_get_managed_tactics` with `include_formation` returns the name the game's own naming code gives each of its 61 symmetric templates, on both builds (for example `4-2-3-1 DM AM Wide`). The team sheet labels the bench: `fm_get_managed_team_sheet` returns `bench_end`, `bench_count` and each substitute's `bench_ordinal`, from the end the game stored in the selection for a fixture, or, while the game has stored none, from the selection screen's own rule (eleven plus the named-substitute cap of the team's next fixture), and says which in `bench_boundary_source`. With the bench known, `fm_get_player_injury_status` without `player_refs` reports the picked eleven and bench, and `fm_report_simultaneous_bench_cover` answers. The opt-in `native_goal_area` of `fm_get_current_match_frame` is no longer withheld. `fm_status` on 27.0.1 resolves every address value (2,620 of 2,620), lists no partial tool, and lists a check of the old build's code that another check replaces under `replaced_checks` instead of `partial_tools`, so the retained crossing tool no longer reads as partial. [docs/builds/27.0.1.md](docs/builds/27.0.1.md) and [docs/current-formation-boundary.md](docs/current-formation-boundary.md) give the evidence and what is not verified.

A goal the game has already shown is photographed from the one frame the game keeps, the ball in the net. Version 0.171.0 added Enhance Mode: "send that Henrique goal to Enhance Mode" turns a goal from the running career into a photorealistic press photograph. `fm_enhance_goal` starts one resumable job and `fm_enhance_status` reports it (198 tools).
