# Persisted native period observations

A normal requested `fm_get_current_match` read now preserves a small private host observation when the exact current fixture, native period stops, event clock domain and both attempt oracles are verified. Capture happens only after the existing consumed-byte/process recheck. No polling, native game function, UI control or disk-save scan is added. No new configuration is required; the existing FM cache directory is used. `host_period_capture` reports captured/already_captured or an explicit reason. Host storage failure preserves the successful live report. Private source bytes/pointers are removed from the response.

`fm_report_retained_match_periods(session_id, fixture_ref)` is the after-match interface. It captures one exact retained result and validates canonical team totals/actors, then matches the complete previously observed attempt prefix, fixture identity, career identity and process/load epoch. A later process/load may reuse only an explicitly finalized full retained semantic fingerprint. It returns historical host provenance, native intervals, classified attempt rows and per-period computed totals. It does not claim an official halftime xG counter or a causal effect of changes.

Official match IDs and fixture dates can repeat after a replay/reload. Observations with the same UID/periods but different semantic prefixes remain separate. Finalized alternative playthroughs use distinct full-source fingerprint pins. Exact per-event semantics, not UID alone or record-pointer bytes, decide continuity. Conflicting matching boundaries fail closed.

Only closed source-proved intervals receive period labels. A halftime read preserves the first half; a later second-half read can preserve its start. A verified terminal stop at current=buffered maximum closes the second half. If that evidence was never captured, the historical second half remains unassigned. At least three completed attempt witnesses are required. Equal/crossing boundaries, absent sources, extra/ambiguous period sequences and unreconciled attempts remain unknown. No period is inferred from event order, gaps, score, coordinates or changing ends.

The host store uses owner-private files/directories, no-follow guarded bounded reads, digest checks, a per-career lock, atomic writes, at most64fixtures/career,8observations/fixture and256KiB/fixture. It never scans whole careers. The reader finalizes exact local linkage only; user datasets are not silently edited. Dataset exporters may consume the explicit result packet through their existing independently validated optional period-evidence contract.

Source controls include frozen authentic Southampton136523 and fresh live Forest11November2030 at native halftime11655, with a subsequent candidate default query successfully capturing source-corroborated evidence. These are distinct observations; no old Southampton or Forest cutoffs are hardcoded. Tests exhaust source identity, process/load change, replayed UID conflicts, event-prefix corruption, native intervals, boundary ambiguity, private storage and default-hook failure behavior.

The optional retained-pass-period module preserves two separate compact witnesses from the original verified capture. The original `pass_event_fingerprint` includes all native flags and remains immutable. A new `pass_period_report_fingerprint` binds the period network's event IDs, original actor/recipient slots, side, category, native start/end clocks and selection mask0x8. Other flag bits, pointers and geometry are not consumed or certified by this report. Whole-fixture player counter reconciliation remains independently required.

Shot/period continuity remains independently assessable when a pass witness differs. Responses expose strict full-flags and report-field continuity separately. Legacy strict observations are not upgraded from retained bytes. A new report witness must come from an original live observation or an explicit, hash-checked authentic terminal bundle preserving original observation time and source provenance. Missing optional support does not break normal current-shot capture. Runtime never loads evidence/test files automatically.
